## Target Filename Convention

Both datasets use the same naming format so `StyleTransferDataset` can parse them identically:

```
<content_basename>&&<style_basename>.png
```

**OmniStyle example:**
```
park_A park with an arched stone bridge.png&&s0415____0926_01_query_0_img.jpeg.jpg.png
│                                          │                                        │
└── content filename                       └── style filename                       └── extra .png suffix
```

**ImagePulse example:**
```
1744911585168919100.png&&1744911585780006862.png.png
│                       │                       │
└── content (image_1)   └── style (image_2)     └── extra .png suffix
```

Parsing logic in `StyleTransferDataset.__getitem__`:
- Split on `&&` -> `content_name_raw`, `style_name_raw`
- `content_path = content_dir / content_name_raw`
- `style_path = style_dir / style_name_raw[:-4]`  (strip trailing `.png`)

## Dataset Statistics

| Dataset | Triplets | Unique Content | Unique Style | Train | Val | Disk |
|---------|----------|---------------|-------------|-------|-----|------|
| OmniStyle-150K | 143,992 | 1,812 | 950 | 129,593 | 14,399 | 187G |
| ImagePulse (100 archives) | 19,953 | ~19,953 | ~19,953 | 17,958 | 1,995 | 102G |

**Key difference:** OmniStyle has high style diversity per content image (~80 styles per content) but very few unique content images (1,812), causing overfitting. ImagePulse has much higher content diversity (~20k unique) but only 1 target per pair.

## Train/Val Split

Generated by `prepare_data.py --val_ratio 0.10 --seed 42`.

Split files are newline-separated lists of target filenames. Both `build_dataset()` and `build_curriculum_dataset()` in `utils/data.py` read these files via `_read_file_list()`. If the files don't exist, fallback to random split at runtime.

## Curriculum Mixed Training

During mixed fine-tuning, `CurriculumMixedDataset` samples from OmniStyle (old) and ImagePulse (new) with a dynamic ratio:

- Epoch 1: 70% OmniStyle / 30% ImagePulse
- Epoch 10: 30% OmniStyle / 70% ImagePulse
- Effective epoch size: `max(old_len, new_len)` = 129,593
- ImagePulse samples are repeated ~2x per epoch at 30% ratio

## ImagePulse JSON Schema

Each `.json` in `extracted/` contains:

| Field | Description |
|-------|-------------|
| `image_1` | Content image filename (.png) |
| `image_2` | Style reference filename (.png) |
| `image_3` | Low-quality intermediate (unused) |
| `image_4` | Final style-transferred result (.png) |
| `editing_instruction` | Text instruction: image_1 -> image_4 |
| `reverse_editing_instruction` | Text instruction: image_4 -> image_1 |
| `image_content_description` | Content description |
| `image_1_preference_score` | Quality score for content image |
| `image_4_preference_score` | Quality score for target image |
| `artifacts_in_image_1` | Boolean artifact flag |
| `artifacts_in_image_4` | Boolean artifact flag |
